# 二次核实与最小修订

日期：2026-10-25。核实基线：本地 `master`，提交 `e0d0bd1`。附件实际列出 5 项，逐项结论如下。

| 项目 | 核实结论 | 最小处理 |
| --- | --- | --- |
| 1. Unix 发布依赖硬链接 | 属实，但不能概括为所有 NFS/SMB 都不支持。目标卷不支持硬链接时，旧实现会在发布阶段失败。 | Linux 优先使用 `renameat2(RENAME_NOREPLACE)`，macOS 使用 `renameatx_np(RENAME_EXCL)`；通过 `os.Root` 打开的父目录描述符执行。系统不支持排他重命名时保留硬链接降级，不引入可能覆盖现有文件的普通 Rename。 |
| 2. 清单审查缓存清空 | 属实。已有 8 条有效记录后，第 9 次插入会清空原记录。不是第 8 次插入，也不影响不使用该 token 的普通下载预览接口。 | 保留 8 条上限及 30 分钟过期策略；容量满时仅淘汰创建时间最早的一条。 |
| 3. 损坏数据阻止重置 | 部分属实。已确认的清理在配置/数据库损坏后无法恢复确实存在；没有安全范围时拒绝删除则是必要保护。 | 新的已确认重置记录保存版本及受保护目录。恢复优先检查当前可读信息，仅在元数据不可读且有有效安全范围时，重建固定白名单执行已确认重置。没有范围、旧记录缺范围、保护目录非法或当前已知目录重叠时继续拒绝删除。 |
| 4. Windows 云目录误拦截 | 属实。原实现把所有重解析点和 `ModeIrregular` 一并拒绝，会误拦截 Cloud Filter 占位目录。 | 读取具体 tag，放行 `CLOUD` 与 `CLOUD_1..F`；符号链接、联接、卷挂载点、未知 tag 和读取 tag 失败仍拒绝。 |
| 5. 评论链接指向根消息 | 属实，但限定为频道链接的 `?comment=<讨论串根消息 ID>`；普通讨论组根消息直链不走这段逻辑。 | 将根消息自身纳入讨论串校验，保留现有回复关系和 peer 来源检查。 |

普通 Unix `rename` 会替换已存在的目标，存在性检查与后续重命名之间也可能插入其他进程的写入，因此没有采用附件提出的这一降级方式。依据：[Linux rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html)。如果某文件系统同时不支持排他重命名和硬链接，仍返回错误，不牺牲防覆盖保证。

Windows 使用 `FindFirstFile` 返回的具体重解析 tag 分类；只放行已知云占位标签，未将所有非符号链接标签一概放开。标签与查询字段依据：[Microsoft Reparse Point Tags](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-point-tags)。

## 重置恢复的保护边界

- 不忽略损坏数据库中的历史下载保护，也不自动批准新的删除操作。
- 新记录中的保护目录来自确认前成功读取和校验的设置、历史任务目录；不复制完整配置或会话凭据。
- 配置损坏时，只有有效的新版已确认重置记录可以恢复；旧记录仍需可读元数据。
- 当前可读配置已知的下载/自定义目录重叠优先拒绝，旧快照不能覆盖这一保护。
- 恢复仍重新生成固定删除名单，不执行记录文件提供的任意 `targets`。
- 未事先确认的损坏数据库仍拒绝盲删，因此不声称任意损坏数据都能自动自愈。
