# 0.23.2 磁盘上限与完成清单审查

审查对象为下载磁盘使用率限制、完成项自动清单、设置及任务提示的工作区改动。

## 修复

- 自动清单原先使用全局导入清单 Registry，第 257 个自动清单会触发会话数量上限，导致后续下载及导入失败。改用任务运行期间持有的清单会话，收尾后释放，不占用导入缓存。
- 已发布文件若清单追加失败，重试原先会直接跳过已完成断点，导致清单永久漏项。恢复时以来源、媒体身份、原名、大小和 SHA-256 核对本地完成文件，补记清单及实际保存名；覆盖自动清单、导入清单与应用重启场景。
- 磁盘停止原先会把已发生文件保存失败的任务标记为成功。保留失败状态和停止原因；空间保护也不再覆盖独立的执行错误。
- 用户取消与磁盘探测同时发生时，原先可能记录磁盘停止并转为完成。探测在读取容量前及保存新错误前检查上下文，保留已发生的用户取消。
- 同步应用内教程、外部教程及版本号为 0.23.2。

新增回归在修复前复现了第 257 个自动清单失败、文件失败被磁盘停止掩盖、用户取消被误判三个问题；修复后通过。另验证清单写入失败并重启后的补记、并行分片扩展、外部空间消耗、并发下载收尾与通知持久化。

## 验证

- `src/build.ps1`：绑定重新生成、冻结锁文件安装、前端类型检查/生产构建、8 项前端回归、Go 全量测试、`go vet ./...`、Windows amd64 Wails 生产构建通过。
- `go build ./...` 通过。

- `git diff --check` 通过。
